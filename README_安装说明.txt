【一、这个版本有什么不同】

1. 一份 DLL 覆盖 Creo 6.0 及以上版本
   本 DLL 使用 Creo 6.0 的 Toolkit 编译。PTC 官方兼容规则：
   用较旧版本 Toolkit 编译出的程序可以在相同或更新的 Creo 上运行
   （"Creo Parametric build newer than Creo TOOLKIT build: always
   supported"），反过来则不被支持。所以这一份 H.dll 可以直接用于
   Creo 6.0 / 7.0 / 8.0 / 9.0 / 10.0 / 11.0 / 12.0。
   （官方原话还有一句"many, but not all cases" —— 本插件只用了
   十多年未变的稳定 API，实测路径封闭，正常不会有问题；万一某个
   新版本出现异常，用该版本的 Toolkit 重新编译即可，源码不用改。）

2. 加载后功能区自动出现「HA」选项卡，不用再手工拖按钮
   插件目录 text\ribbon\toolkitribbonui.rbn 会在插件加载时被
   Creo 自动读取：它把 6 个组挂到工程图模式的功能区上，从左到右是
      注释  →  会话  →  球标  →  功能  →  3D  →  绘图比例
   打开任何一张工程图，选项卡栏最右侧就是「HA」
   （与 Creo 自己的「注释」页签并列，其它模式下不会出现，干净不碍事）。

3. 路径全自动，不用改源码、不用设 pro_symbol_dir
   插件运行时自己查 DLL 所在目录，日志和符号目录都由它推算。
   整个 H 文件夹拷到任何位置都能用（仍建议用英文无空格路径）。

【三、安装步骤】

第 1 步  放置文件
  把整个 H 文件夹复制到一个【纯英文、无空格】的目录，例如
      D:\H
  路径里不要有中文和空格，这是 Creo 插件的最佳实践，能避免
  绝大多数莫名的加载问题。

第 2 步  修正注册文件路径
  如果没有放在 D:\H，就双击运行 setup.bat，
  它会自动把 H.dat 里的两行路径改成当前文件夹的绝对路径。
  也可以手工用记事本打开 H.dat，改这两行：
        exec_file  <你的目录>\H.dll
        text_dir   <你的目录>\text

第 3 步  让 Creo 加载插件，两种方式任选

  方式 A（推荐，长期生效）
    记事本打开 Creo 的 config.pro，加入一行：
protkdat D:\H\H.dat（文件夹路径）
    保存后重启 Creo。

  方式 B（临时注册）
    Creo 菜单  文件 -> 选项 -> 配置编辑器，
    或  工具 -> 辅助应用程序 -> 注册 -> 选中 H.dat -> 启动

第 4 步  开始使用
  打开一张工程图，功能区选项卡栏最右侧会出现「HA」选项卡：
      添加球标    点一下图纸位置放一个圆圈球标，编号自动 +1（追加在末尾）
                  支持连续放置：放完一个直接点下一个位置，不用再点按钮，
                  全部放完按鼠标中键（或右键）结束
      插入球标    在中间“补插”一个：先点放置位置，再点一个已有球标，
                  新球标就用那个编号，它以及比它大的号全部自动 +1
      删除球标    点选要删除的球标，删除后其余序号自动重排（后面的号补齐）
      重排序号    把所有球标压实成 1、2、3…（用来补齐删除后留下的空号）
      重点尺寸    连点尺寸，点一个标一个，在尺寸文本【前面】加 ★
                  （已有 ★ 的自动跳过，原来带的前缀会保留，如 2x → ★2x）
      取消重点尺寸 同样连点尺寸，把前缀里的 ★ 去掉
      技术要求    弹出 Creo 原生文件浏览器（默认停在插件目录的
                  templates 文件夹下「技术要求」子目录），选一个 .txt，
                  整段变成一条多行注解，再点放置位置即可
                  每行最多 80 字、一个模板最多 64 行；UTF-8 / GBK 都能读
      打开工作目录 用资源管理器打开当前 Creo 工作目录
      会话操作 ▾  下拉 6 项：设置工作目录 / 打开模型目录 / 模型转目录 /
                  批量删旧版 / 删除闲置模型 / 清理垃圾
                  （两个删除功能会先扫描计数，要你在消息行输入 Y 确认才动手，
                    只删当前工作目录、不递归子目录；「删旧版」还要求同目录存在
                    无编号的同名文件才删，避免删掉唯一副本）
      3D 组       全部小按钮，处理当前零件 / 装配本身（在工程图里
                  点也认，会自动改用
                  这张图关联的模型）：
                  轮廓尺寸      弹窗列出 X / Y / Z 外形尺寸
                  显示控制 ▾    下拉 4 项：隐藏零件 / 反隐藏零件（切换）/
                                全部隐藏 / 全部显示
                                （隐藏和取消隐藏要点选对象后中键确认；
                                  全部显示是遍历所有特征逐个恢复）
                  重命名        消息行输入新名，同名工程图会跟着改
                  装配着色      每个元件不同颜色，同一零件同色
                  零件着色      整个模型涂一个随机颜色
                  清除着色      外观属性传 NULL，恢复默认外观
                  原位打开      选一个元件，按装配当前视角单独打开
                  批量备份      选目录，模型连同全部子模型一起备份
                  ★ 除绘图页签里的这个 3D 组，rbn 里还给零件 / 装配 /
                    钣金三个窗口各挂了一个「HA」页签（会话 + 3D 两个组，
                    顺序同绘图页签），容器名
                    分别是 prt_main_adb_cat / asm_main_adb_cat /
                    prt_smt_main_adb_cat（绘图是 drw_main_adb_cat，启动页
                    是 main_adb_cat）。这五个名字在 Creo 6 与 Creo 12 的
                    资源 DLL 里都有，所以两个版本都认。
      绘图比例    1:1 1:2 1:3 / 2:1 3:1 4:1 六个常用档直接显示，
                  右边「更多比例 ▾」下拉里还有 18 档 + 自定义比例
                  （自定义在消息行输入：1:2.5、2.5:1、0.4、1/3 都认，全角冒号也认）
      注释组      ★ 这一组【不是插件实现的功能】，而是直接引用 Creo 自己的
                  绘图注释命令：尺寸 / 几何公差 / 纵坐标尺寸 / 注解▾（4 项：
                  分离的注解 / 偏移注解 / 顶上注解 / 引线注解）/ 表面粗糙度 /
                  显示模型注释 / 设置基准 / 绘制基准目标 / 绘制基准平面 / 绘制基准轴
                  图标、文字、灰化状态、自带下拉都是 Creo 提供的，
                  行为和原生「注释」页签一模一样，所以出图时不用来回切页签
                  （这些命令名在 Creo 6 和 Creo 12 里都存在，两版通用）
      一键导出图纸  弹出 Creo 自己的「保存」浏览器：选好目录、填好文件名即可，
                  一次生成三个同目录同名的文件：
                  <名字>.stp  该工程图关联的 3D 模型（STEP）
                  <名字>.pdf  工程图本身，600 dpi 单色
                  <名字>.dwg  工程图本身（AutoCAD DWG）
                  中文文件名没问题：Creo 的 DWG 导出器不认中文名，
                  插件会先用英文临时名导出、再自动改名搬到你要的位置
                  图纸没关联 3D 模型时只导 PDF 和 DWG 并给出提示
      视图动态调整  在原生「选择」对话框里选中一个普通视图（必须是 General 且无子视图）点「确定」，
                  然后直接移动鼠标就能全方位旋转该视图（上下移 = 绕图纸水平轴转，左右移 = 绕图纸竖直轴转），
                  控制灵敏度适中；中键 = 确定完成，Esc = 取消并精确恢复原朝向
      公差刷子     点选一个【源尺寸】读走它的整套公差（类型 / 上·下公差值 / 公差表 / 小数位），
                  然后逐个点其它尺寸就立刻把同一套公差刷过去（点一个刷一个，个数不限），
                  中键或 Esc 结束；参考尺寸/从动尺寸不能设公差，刷到会提示跳过
                  （公差要在界面上看得见，config 选项 tol_display 需为 yes）
  点「添加球标」后，消息区提示「请点击图纸位置放置球标。」，
  然后在图纸上任意位置点一下即可。

  ★ 连续放置
    放完一个不用再去点按钮 —— 命令不会退出，直接点下一个位置就继续放，
    编号接着往下排（每次都取当前最大号 +1）。此时消息区提示
    「继续点击放置球标；按中键或右键结束。」。
    结束方式任选：鼠标中键（滚轮按下）、右键、或按 Esc；
    直接去点功能区上别的命令也可以，会自动收尾。
    放完多个后消息区会提示「连续放置已结束。」。

  典型场景 —— 图纸上已排好 1~18 号，现在发现漏了一个尺寸要插在 12 号前面：
      1) 在工程图里把这个尺寸标出来；
      2) 点「插入球标」，在新尺寸旁边点一下放置位置；
      3) 再点一下现在显示 12 的那个球标。
    结果：新球标自动变成 12 号，原来的 12~18 全部变成 13~19 号，
    位置都不用动，一次点完。

【四、如果功能区没有自动出现「HA」选项卡】

正常情况下 text\ribbon\toolkitribbonui.rbn 会被自动读取。万一某个
Creo 版本对 rbn 更挑剔而没生效，手工补一次即可（对同一版本一劳永逸）：

  1) config.pro 里加：  tk_enable_ribbon_custom_save yes
  2) 重启 Creo，确认插件已加载。
  3) 文件 -> 选项 -> 自定义功能区
     右侧列表里新建一个选项卡并改名 H，再新建一个组；
     左侧「从下列位置选择命令」下拉框选 All ProTk Commands
     （中文界面是「所有 ProTk 命令」），
     把插件自己的命令（添加球标 / 插入球标 / 删除球标 / 重排序号 /
     一键导出图纸 / 视图动态调整 / 公差刷子 / 技术要求 / 重点尺寸 /
     取消重点尺寸 / 绘图比例 / 会话操作 / 轮廓尺寸 / 隐藏 / 取消隐藏 /
     全部显示 / 重命名 / 随机着色 / 清除着色 / 原位打开 / 批量备份 /
     简化助手…）添加进来。
     注意：注释组那 10 项是 Creo 的系统命令，不在这里，
     它们直接从 rbn 里引用名字，不需要 Designate。
  4) 点 导入/导出 -> 保存辅助应用程序用户界面
     （Save the Auxiliary Application User Interface），
     它会在本插件的 text 目录下生成正规格式的
     toolkitribbonui.rbn；把它复制覆盖 text\ribbon\ 下的同名文件，
     再点 应用 / OK。
  5) 之后把这个新生成的 rbn 一起拷给别人，别人就全自动了。

  说明：官方文档写明生成 rbn 需要 Creo 的 TOOLKIT 开发许可，
  且不能用文本编辑器手改。本插件已经附了一个手工编写的 rbn，
  正常直接用；实在不生效时再按上面步骤生成一份正规的。

【五、故障排查】

  插件同目录下会自动生成 h_load.log，记录每次加载的关键结果：
      plugin_dir=...              插件实际所在目录
      symbols_dir=...             符号目录
      creo version=... build=...  当前 Creo 版本
      ProCmdActionAdd(...) -> 0       0 = 成功
      ProCmdDesignate(...) -> 0       0 = 成功（旧版本可能返回 -28，
                                      那是「命令描述」这一栏没配，
                                      不影响按钮功能，可忽略）
      ProRibbonDefinitionfileLoad(...) -> 0   功能区定义文件加载成功
      HLoadSymbol: <目录>\symbols\123.sym -> EXISTS / MISSING!
                                      符号文件在不在（MISSING! 表示发出去的
                                      包不完整，少了 symbols 文件夹）
      HLoadSymbol: [1] "." -> 0       第 1 条路成功（相对 pro_symbol_dir）
      HLoadSymbol: [2] copy to cwd ... -> 0
                                      第 2 条路成功（把符号复制到 Creo 工作目录）
      HLoadSymbol: [3] SRC_PATH abs dir -> 0
                                      第 3 条路成功（用绝对目录兜底）
      HLoadSymbol: OK via [1|2|3]     最终走通的是哪一条
      HAddAct: MousePick status=0 btn=1   拾取到左键（btn=4 是中键，
                                      btn=2 是右键，都会结束连续放置）
                                      status 非 0 表示用户按了 Esc 或
                                      点了别的命令
      HAddAct: ... placed=3           本条日志时，这次命令里已放下第 3 个
      HCreateBalloon: number=12 OK    球标创建成功，编号 12
      HAddAct: finished, placed=4     本次连续放置一共放了 4 个
      HShiftNumbers: from=12 delta=1 affected=7
                                      插入时把 >=12 的 7 个球标各 +1
      HTechReqAct: file open -> 0     技术要求选好了模板（-1 = 用户取消）
      HTechReqAct: cp=65001 bom=1 lines=12
                                      识别出的编码 / 有无 BOM / 读到几行
      HCreateNoteFromLines: noteCreate -> 0
                                      注解建好了（0 = 成功）
      HKeyDimAct / HKeyDimMark       重点尺寸逐步结果，含
                                      /已跳过/失败/视图重生成/前缀旧长度/写入结果
      native cmd <名字> -> <指针> [FOUND] / [MISSING]
                                      注释组原生命令名的存在性自检。全部 FOUND 说明
                                      这批按钮在当前 Creo 版本上一定可用；
                                      某个 MISSING 就是该版本没这个命令

  其中 ProRibbonDefinitionfileLoad 这一行的返回码最有用：
      0  = 功能区定义加载成功（选项卡应该出现了）
     -4  = 文件没找到。确认 text\ribbon\toolkitribbonui.rbn 存在；
           注意必须放在 text 下的 ribbon 子目录里（这是 Creo 官方
           规定的搜索路径：<text目录>\ribbon）。
    -16  = 文件找到了但不是合法的功能区定义（格式问题），
           按第四节用 Creo 自带的自定义功能区导出一份正规的即可。
      另一行带完整路径的调用是绝对路径兜底，正常情况下不需要看。

  常见现象：
  * 提示「未找到球标符号文件」
      【原因】ProDrawingDtlsymdefRetrieve 的路径参数在官方头文件里写得很
      明确：它是「相对 pro_symbol_dir 的相对路径」，pro_symbol_dir 没设
      时才用 Creo 的工作目录。所以"给个绝对路径"是没用的 —— 这是本插件
      在别人机器上第一次报这个错的原因，现已改为三条路依次尝试。

      1) 先看日志那行 EXISTS / MISSING!：
         MISSING! 说明 H.dll 旁边根本没有 symbols\123.sym，
         就是发出去的包不完整 —— 重新完整解压 H.zip 即可。
      2) 三条路各自失败的原因：
         [1] 相对 pro_symbol_dir（没设=工作目录）——对方既没设
             pro_symbol_dir、工作目录里也没有该符号时失败；
         [2] 复制自带符号到工作目录后重试——工作目录只读（比如工程图
             放在网盘、只读盘）时会失败；
         [3] 绝对目录加载——最后兜底。
      3) 手动兜底（立刻可用，二选一）：
         · 把 H\symbols\123.sym 复制到 Creo 当前工作目录（就是打开
           工程图时"工作目录"那一栏显示的文件夹），再点一次按钮；
         · 或在 config.pro 里把 pro_symbol_dir 指向 H\symbols：
               pro_symbol_dir D:\H\symbols
           注意：如果 config.pro 里【已经有】pro_symbol_dir 这一行，
           就不要再加第二行（会冲突），直接把它指向的那个目录里放一份
           123.sym 即可。
  * 提示「请在工程图界面执行此命令」
      这些命令只能在工程图（Drawing）中使用，先打开一张工程图。
  * 日志里 ProCmdDesignate(...) -> -28
      单独出现 -28 不用紧张（历代 Creo 都这样，按钮照常能用）。
      但如果同时 ProRibbonDefinitionfileLoad 也返回 -4，说明 Creo
      确实没读到插件目录：用记事本打开 H.dat 检查 text_dir 这一行，
      结尾必须是 <目录>\text（反斜杠 + 字母 text）；如果 \text 被
      写成了制表符或丢了字母，手工改正这一行即可。
  * ProCmdDesignate 是 0，但功能区还是没有「HA」选项卡
      看 h_load.log 里 ProRibbonDefinitionfileLoad 的返回码：
      0 说明加载成功，那就在工程图界面看选项卡栏（球标选项卡只在
      工程图模式下出现）；-4 / -16 按上面的说明处理。
  * 找不到「保存辅助应用程序用户界面」这个按钮
      先在 config.pro 里加 tk_enable_ribbon_custom_save yes
      并重启 Creo，该按钮才会出现。

【六、重新编译（可选）】

  需要 Visual Studio 2022（含 C++ 生成工具）和 Creo 6.0 的
  Toolkit 开发包。把 Toolkit 的 includes 与 x86e_win64\obj 路径
  填进 makefile 的 CREO6_SDK 变量，然后双击 build.bat 即可。

  提示：Creo 安装介质里自带 Toolkit。如果安装 Creo 时没有勾选
  「API Toolkits / Creo Parametric TOOLKIT」组件，用 Creo 安装程序
  修改安装、勾上该组件即可装好。

【七、★发给别人之前：必须先解锁（重要）】

  别人打开 Creo 时弹出这个框，就是这个原因：

      ┌──────────────────────────────────────────────┐
      │ 消息                                          │
      │ Creo Toolkit 应用程序 "H" 在分配到您的位置    │
      │ 之前未被解锁。请联系 "H" 的提供者获得协助。   │
      └──────────────────────────────────────────────┘

  这不是插件写错了，是 PTC 对 TOOLKIT 插件的统一规定：
  用 TOOLKIT 编译出来的 DLL 默认是【锁定】状态，只有装了
  Creo Parametric TOOLKIT 开发许可的电脑（=你这台开发机）
  才能加载。要给别人用，必须先"解锁"。

  解锁方法（一分钟）：

      1) 完全退出 Creo（任务管理器里确认没有 xtop.exe）
      2) 双击插件目录里的 unlock.bat
      3) 看到「解锁成功」即可，然后把 H 文件夹打包发给别人

  unlock.bat 会自动找到 Creo 自带的解锁程序
  （<Creo安装目录>\Parametric\bin\protk_unlock.bat）并调用它。
  万一自动找不到，把那个 protk_unlock.bat 拖到 unlock.bat 上松手。

  ★ 两条铁律，务必记住：
    · 每次重新编译 H.dll 之后，都要重新跑一次 unlock.bat
      （链接时会重新写入"锁定"标记，之前的解锁状态会丢）
    · 解锁之后不要再改动 H.dll 哪怕一个字节
      （改动后 Creo 会重新把它当成锁定状态）

  解锁过程会占用一个 TOOLKIT 许可几秒钟（最长 15 分钟），正常现象。
  本机测试时用的是 Creo 12 的许可解锁；若某台老版本 Creo 仍提示
  未解锁，在那台机器上用该版本的 protk_unlock 重新解锁一次即可。

====================================================================
  八、球标符号文件（决定同事的电脑能不能用）
====================================================================

  symbols\123.sym 就是球标的样子：一个圆圈 + 中间一个序号变量。

  ★ Creo 的文件只"向上兼容"：新版 Creo 能读旧版文件，
    旧版 Creo 读不了新版文件。符号文件 .sym 一模一样。

  用记事本打开任何 .sym，第 11 行就写着它是哪个版本存的：

      #Creo  TM  6.0  (c) 2026 by PTC Inc.  All Rights Reserved. 6.0.2.0
                  ^^^ 这里

  第 1 行的第 9 个数字是"格式级别"，随版本递增：

      Creo 3.0 = 3400      Creo 6.0 = 3700      Creo 12 = 4300

  ⚠ 三条规矩：
    · 本插件用的是 123.sym（Creo 6.0.2.0 存出，格式级别 3700），
      Creo 6 / 7 / 8 / 9 / 10 / 11 / 12 全都能读，一份通吃。
    · 千万别用新版 Creo 打开它再"保存" —— 保存会把它升级成新版格式，
      同事的 Creo 6 立刻就读不了了。
    · 以后要换符号也一样：发给谁，就用【对方那个版本或更老】的 Creo 去存。

  报"球标符号加载失败"时：打开 D:\H\h_load.log（每次启动都写），
  里面会写明符号文件在不在（EXISTS / MISSING）、三条加载路径各自的返回码，
  把这个日志发出来就能定位。

  留个记录，免得以后重走弯路：
    最早用的是 111.sym，它是 Creo 12.4 存的（第 11 行写着 12.4.0.0，
    格式级别 4300，正文还带 symbol_font / p_sym_param 等 Creo 8/9
    才有的字段）。它在 Creo 12 上完全正常，但在 Creo 6 上被 Creo 自己
    拒绝解析 —— 光把头部版本号改成 Creo 3.0 也没救，因为正文字段本身
    就是新版才有的。换成 Creo 6 存出的 123.sym 后彻底解决。
====================================================================
  九、Creo 自己起不来时（授权问题，与本插件无关）
====================================================================

  如果 Creo 还没进到界面就弹出这样的框：

      ┌──────────────────────────────────────────────┐
      │  Warning Message List                         │
      │   License request failed for feature          │
      │                                               │
      │   Requesting PROE_DesignEss ...               │
      └──────────────────────────────────────────────┘
      （点 OK 之后界面变成英文，或者干脆起不来）

  这是【Creo 授权过期 / 许可证服务连不上】，不是插件的错 ——
  此刻插件根本还没被加载。判断依据：同样的文字会原样写进
  Creo 工作目录（启动 Creo 时"工作目录"那一栏）下的 std.out，
  例如：

      License request failed for feature
      Requesting PROE_DesignEss ...
      7788@laptop-uf8mv9bq: (-61) Cannot read license file data
      from license server system.

  PROE_DesignEss 这个名字来自 Creo 自己的启动配置，跟 H.dat /
  H.dll 一点关系都没有。可以在 Creo 安装目录里搜到它：

      <Creo安装目录>\Parametric\bin\parametric.psf
          ENV=CREOPMA_FEATURE_NAME=PROE_DesignEss (155)

  ★ 顺带一个可以当"体检指标"的现象：同一个授权包里通常还带着
    「Language Option - CHINESE」（特征 155）。授权一过期，Creo
    会跟着打印

      Option Chinese_Translation not ordered ...
      LANG being reset to USASCII

    也就是界面被迫切成英文。看到这两行一起出现，基本可以断定是
    授权到期，而不是别的毛病。

  两种授权方式，查法不同：

    A. 用许可证服务器（本机 7788 端口那种）
       看服务端日志：
         C:\Program Files\PTC\FLEXnet Admin License Server\logs\ptc_d.log
       过期时会直接写：
         (ptc_d) EXPIRED: PROE_DesignEss
         (ptc_d) No features to serve, exiting
       含义 = 授权包已过期，服务端"没有特征可以发"，客户端要不到。

    B. 用独立的 License.txt 文件
       用记事本打开它，搜 INCREMENT，看每行日期，例如：
         INCREMENT PROE_DesignEss ptc_d 43.0 05-oct-2026 1 \
       这行的日期就是到期日，过了就失效。

  处理办法：
    1) 联系授权方（经销商 / PTC）续订，或拿一份新的 License Pack；
    2) 新包用 FLEXnet Admin License Server 控制台重新加载
       （浏览器打开 http://localhost:7788 ），再重启许可证服务；
    3) 用 Creo 安装目录 Parametric\bin\ptcstatus.bat 验证，
       能看到 PROE_DesignEss 且状态正常就算修好了。

  本机对照（2026-10-09 实测，供参考）：
    Creo 12 → 用 D:\creo1\...\License\License.txt（独立文件）→ 正常
    Creo 6  → 用 7788@laptop-uf8mv9bq（本机许可证服务）→ 授权包已于
              2026-10-05 到期，服务端"无特征可发"，所以 Creo 6 起不来
